Deep file review

Reviewed 36 of 40 selected files, in risk order.

backend/libs/session/src/broker/swarm-container-manager.ts

high Swarm mode silently runs agent containers without the egress firewall
In createContainer(): fleet binds fail closed ('MOUNT_UNSUPPORTED_IN_MODE' throw when extraBinds/protectedBinds present), but the egress firewall fails OPEN — `if (config.firewall && config.firewall.kind !== 'open') { this.deps.warn?.(`swarm mode ignores the egress firewall for session ${config.sessionId} (not yet supported)`) }` merely logs and proceeds. The container then runs unconfined even when the lifecycle planned a `network: off`/restricted plan.
Fix: Refuse to start (as with mounts) when a non-open firewall plan is requested but cannot be enforced in swarm mode, or implement the swarm egress firewall before allowing such sessions. Agents carry minted credentials, so an unconfined runtime is an exfiltration path.
Effort: M
Also involves: backend/libs/session/src/session-lifecycle.service.ts, docs/session-lifecycle.md

backend/libs/credential/src/provider-connection.service.ts

medium Unknown providerType in beginConnect silently falls through to the GitHub adapter
`const provider = this.remoteProviders.get(input.providerType) ?? this.requireProvider('GitHub')` with the comment "an unknown providerType has always taken the GitHub arm. Do not tighten to a throw." A caller-supplied providerType that is not registered begins a GitHub App/OAuth flow instead of being rejected, using GitHub's client credentials for an unrelated request.
Fix: Reject unrecognized providerType values with an explicit error rather than defaulting to GitHub; if legacy compatibility is required, gate the fallthrough to a known legacy value only.
Effort: S
Also involves: backend/libs/credential/src/provider-connection.service.test.ts

backend/libs/session/src/skaile-config.service.ts

medium Connector flag compare-and-swap excludes providerLinkId, allowing an unnoticed repoint under concurrency
`connectorFlagCasProjection` destructures out `providerLinkId` and `label` before building the CAS projection ('Provider-link reconciliation may race this CAS legitimately'). `hasSameConnectorFlagCasProjection` therefore treats two connector entries as equal even if their providerLinkId differs, so a flag-update CAS can succeed against a connector whose providerLinkId (which determines which credential/provider link is minted) changed underneath the reader.
Fix: Confirm the owner-mint gate re-validates providerLinkId authority at persist time for every flag write, or include providerLinkId in a stricter guard for security-relevant transitions so a concurrent repoint cannot slip past the CAS.
Effort: M
Also involves: backend/libs/session/src/credential-mediator.service.ts, backend/libs/session/src/skaile-config.service.test.ts

backend/libs/session/src/session-creation.service.ts

low Session slug uniqueness retry does not converge across API replicas
`isSessionSlugUniqueViolation` + MAX_SLUG_CREATE_ATTEMPTS retry loop relies on a process-local repository cache: 'the retry only converges when the winning create happened in this process. Under multiple API replicas the loser exhausts its attempts and surfaces the raw constraint error.' The raw Prisma P2002 then reaches the caller under multi-replica deployments.
Fix: Map the exhausted-retry constraint error to a stable transport-neutral SessionCreationError code, or derive a fresh slug on each retry that does not depend on the local cache, so multi-replica deployments return a clean result.
Effort: M
Also involves: backend/libs/session/src/session-creation.service.test.ts

frontend/src/hooks/use-session-messages.tsx

low Typing-indicator visibility filtering performed client-side
TypingEntry carries `pendingVisibility` with `mode` and `recipientUserIds`, described as 'the F-23 coarse-stripped visibility mode so the viewer can self-filter the typing dot.' If recipientUserIds is delivered to clients for self-filtering, a client can observe who is typing regardless of visibility since enforcement is in the browser.
Fix: Ensure the backend strips recipient identity and suppresses typing events the viewer is not authorized to see before fan-out, rather than relying on the client to self-filter; the client filter should be defense-in-depth only.
Effort: M
Also involves: backend/libs/session/src/session-message.service.test.ts

backend/libs/credential/src/provider-connection.service.test.ts

info Hardcoded credential-like fixtures across provider connect tests
Test fixtures embed credential-looking literals such as `resolveSecret: () => Promise.resolve('the-client-secret')`, GITHUB_APP.clientId 'gh-client-id', SHAREPOINT_APP.clientSecretKey names, and exchangeCode returning access_token 'sp-access-token'/refresh_token 'sp-refresh-token'. These are the likely source of many of the scanner's secrets.credential hits under backend/libs.
Fix: Confirm these are synthetic-only; if the secrets scanner is noisy on them, add them to an allowlist or clearly namespace fixtures (e.g. TEST_ONLY_ prefix) so real credential leaks are not buried in false positives.
Effort: S
Also involves: backend/libs/session/src/credential-mediator.service.test.ts, backend/libs/session/src/session-lifecycle.service.test.ts
